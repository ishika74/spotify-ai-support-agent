# Spotify AI Support Agent

An AI-assisted customer-support prototype built with Python, Streamlit, and Google's Gemini API.

**Live Demo:**  https://spotify-ai-support-agent-8ayxy8hzodn4vhzkipz5un.streamlit.app/

## Overview

Customer-support teams receive repetitive questions about playback, account access, subscriptions, billing, and other issues. This project explores how AI and lightweight natural-language processing techniques can help classify customer messages, identify issues that may need human attention, and generate support responses.

The repository contains two separate workflows:

1. **Streamlit application:** An interactive support-chat interface that uses issue classification, escalation checks, and Google Gemini to generate responses.
2. **Modular support pipeline:** A separate implementation of intent classification, rule-based escalation, historical-conversation retrieval, template-based response drafting, and evaluation utilities.

These workflows share the same project goal but are not a single integrated pipeline. In particular, historical-conversation retrieval in the modular pipeline should not be assumed to ground responses generated by the deployed Streamlit application.

This project is a prototype. It is not an official Spotify product and does not connect to Spotify's internal support systems.

## Features

### Streamlit application

- Interactive customer-support chat interface.
- Support-issue classification.
- Rule-based escalation indicators.
- AI-generated responses through the Google Gemini API.
- Conversation history maintained within the current Streamlit session.
- Response feedback controls.
- Generation and download of support-ticket summaries.

### Modular support pipeline

- Keyword-based intent classification.
- Rule-based escalation detection.
- Reconstruction of customer/support exchanges from conversation data.
- TF-IDF and cosine-similarity retrieval of historical conversations.
- Template-based response drafting.
- Evaluation utilities for classification, escalation, retrieval, and response quality.
- LLM-as-a-judge evaluation with a small human-calibrated example set.

The evaluation components are intended for experimentation. Their presence does not establish that the system has achieved production-level accuracy or reliability.

### Which LLM is used?

The project uses Google's Gemini API. The API key authenticates the application; it does not select the model automatically.

The model is selected separately in `llm_client.py` through the `MODEL_NAME` configuration. The current source sets this value to `gemini-3.6-flash`. Confirm that this model ID is available to your API account and supported by Google's API before relying on it. If necessary, replace it with a supported Gemini model ID.

The modular response generator, `reply_generator.py`, uses templates rather than Gemini for its normal response-drafting workflow.

## Dataset

The project uses a sample of the Customer Support on Twitter dataset, containing customer-support messages and identifiers that can be used to reconstruct conversation exchanges.

The documented columns include:

- `tweet_id`
- `author_id`
- `inbound`
- `created_at`
- `text`
- `response_tweet_id`
- `in_response_to_tweet_id`

The ingestion module prepares customer/support exchanges and can filter for conversations associated with `SpotifyCares`.

The dataset represents historical support conversations. It is not a complete or authoritative source of current Spotify policies.

## Installation and Setup

### Prerequisites

- Python.
- Git.
- A Google Gemini API key for Gemini-powered functionality.
- Internet access for dependency installation and API requests.

### 1. Clone the repository

```bash
git clone https://github.com/ishika74/spotify-ai-support-agent.git
cd spotify-ai-support-agent
```

### 2. Create a virtual environment

```bash
python -m venv venv
```

Activate the environment.

**Windows PowerShell**

```powershell
.\venv\Scripts\Activate.ps1
```

**macOS/Linux**

```bash
source venv/bin/activate
```

### 3. Install dependencies

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### 4. Configure the Gemini API key

Create a `.env` file in the project root:

```env
GOOGLE_API_KEY=your_gemini_api_key
```

The current `llm_client.py` accepts `GOOGLE_API_KEY` and also supports `GEMINI_API_KEY` as a fallback. If both are set, `GOOGLE_API_KEY` takes precedence.

Replace the placeholder with your own key. Never commit API credentials to Git.

### 5. Run the Streamlit application

```bash
python -m streamlit run app.py
```

Open the local URL printed by Streamlit in your browser.

The Streamlit application is the interactive entry point. Running it does not automatically run the evaluation experiments.

## Running the Modular Pipeline

The modular pipeline can be invoked from the command line:

```bash
python pipeline.py "my Spotify keeps skipping songs on my iPhone"
```

The pipeline loads customer-support data, classifies the message, checks escalation rules, retrieves similar historical exchanges, and produces a template-based response.

**Dataset path note:** The current `pipeline.py` resolves its default CSV path to `../data/sample.csv` relative to the script. However, the repository lists `sample.csv` in the project root. Verify that the expected data file exists at the path used by the code before running the pipeline. Update the path or data layout if needed.

## Evaluation

The repository includes evaluation utilities for experimentation with different components.

### Classification

Evaluates intent-classification behavior and compares predictions with simple baselines where implemented.

### Escalation

Examines whether potentially sensitive or high-priority messages are flagged for human review.

### Retrieval

Uses TF-IDF and cosine similarity to find historical conversations that resemble a new customer message.

### LLM-as-a-judge

Evaluates drafted responses across four dimensions:

- **Groundedness:** Whether the response is supported by available examples and avoids unsupported claims.
- **Correctness:** Whether the response is factually sound.
- **Tone:** Whether the response is appropriately phrased.
- **Actionability:** Whether the customer receives useful next steps.

The repository includes a small human-calibrated example set. This is preliminary evaluation, not statistical proof of the judge's reliability.

### Evaluation status

Before running the evaluation suite, verify the current imports and configuration. In the current source, `llm_judge.py` imports `QUALITY_MODEL` from `llm_client.py`, but `llm_client.py` defines `MODEL_NAME` instead. This mismatch may prevent the evaluation code from importing successfully until it is corrected.

Consult `run_eval.py` for the actual command-line entry point and inputs. Do not treat evaluation functionality as fully verified until the scripts run successfully.

## Example Use Case

A customer asks:

> My Spotify keeps stopping every few seconds. What should I do?

In the Streamlit application, the message can be classified, checked against escalation rules, and sent to Gemini to generate a support response.

In the separate modular pipeline, the message can be classified, checked for escalation, compared with historical support exchanges, and answered using a template-based response.

These are different implementations. The modular pipeline's retrieved examples should not be assumed to be included in the deployed app's Gemini prompt.

## Limitations

- The project uses a sample of historical customer-support conversations.
- Keyword-based classification can fail on ambiguous or unfamiliar messages.
- Rule-based escalation detection may miss important cases or flag cases unnecessarily.
- TF-IDF retrieval relies on lexical similarity and may miss semantically related messages.
- Historical support responses may be outdated or unsuitable for a new issue.
- Gemini-generated responses may contain incorrect or unsupported information.
- The LLM-as-a-judge calibration set is small.
- API availability, model access, quotas, and rate limits can affect Gemini-powered functionality.
- Conversation history is maintained within the Streamlit session and is not backed by persistent conversation storage.
- Feedback controls do not imply persistent feedback storage or automatic model improvement.
- Ticket summaries are generated locally and are not submitted to Spotify.
- The application does not implement a verified live-agent handoff.
- The Streamlit app and modular retrieval pipeline are separate workflows.
- The evaluation scripts and setup commands have not been claimed as fully tested end to end.
